### 2.4 健康出参决定：保留完整（不强行脱敏）

**结论**：`app/routers/student_ops.py::_health_dict`（L395-411）返回的 `symptoms` / `handleNotes` **保留完整**，不做掩码。理由：

1. **前端真实消费**：`grade-buddy-scan-main/src/components/student-ops/campus/HealthTab.tsx` 直接展示 `h.symptoms`（L196）与 `handleNotes`（L566），班主任按晨午检流程需要查看/填写具体症状（如「发热38.5℃、咳嗽」）与处理备注（如「已通知家长接回」）。
2. **业务必需**：晨午检的核心价值就是记录并追踪症状明细，掩码后班主任无法履职，会造成功能回退。
3. **合规定位**：健康信息定级 **L4**，但本接口已通过后端鉴权（`bind_grading_user_context`）限定为班级授权教师（班主任/管理员），属「最小授权下的授权访问」。文档标注：**L4+ 授权班主任**，访问留痕已有 `access_logs`（E03+E14）。
4. **兜底**：若未来接入家长端/更广泛角色，再对 `symptoms`/`handleNotes` 应用 `mask_address` 风格的模糊化或禁止出参。

## 3. 脱敏规则库

> 实现：`app/services/field_masking.py`（纯函数，全部有单测，见 `tests/test_e09_field_masking.py`）。
> 规则与实现同步，改规则需同步本表。

### 3.1 手机 / 电话掩码 `mask_phone`

| 输入长度  | 规则       | 示例                          |
| --------- | ---------- | ----------------------------- |
| 空 / None | 返回空串   | `""`                          |
| ≤ 4       | 整体掩码   | `1380` → `****`               |
| 5-7       | 保留前2后2 | `1234567` → `12***67`         |
| ≥ 8       | 保留前3后4 | `13800138000` → `138****8000` |

### 3.2 学籍号掩码 `mask_student_number`

| 输入长度        | 规则           | 示例                    |
| --------------- | -------------- | ----------------------- |
| 空 / None       | 返回空串       | `""`                    |
| ≤ keep（默认2） | 整体掩码       | `23` → `**`             |
| ≤ 2*keep        | 保留末 keep 位 | `234` → `*34`           |
| 其余            | 保留前2后2     | `23001189` → `23****89` |

> **统一口径**：学籍号掩码采用「保留前2后2」(`23****89`)，与手机「前3后4」风格一致。不采用「仅末4位」，因末 4 位常为顺序号，保留前2后2可隐藏更多中间语义位（年份/校区码）。

### 3.3 住址掩码 `mask_address`

| 场景                                    | 规则                        | 示例                                                     |
| --------------------------------------- | --------------------------- | -------------------------------------------------------- |
| 空 / None                               | 返回空串                    | `""`                                                     |
| 含省/市/区县                            | 仅保留省+市+区县，其余 `**` | `广东省深圳市南山区科技园路1号` → `广东省深圳市南山区**` |
| 仅省+市                                 | 原样保留                    | `江苏省南京市` → `江苏省南京市`                          |
| 无法识别行政区划（如「幸福小区3号楼」） | 整体掩码（最长8位）         | `幸福小区3号楼` → `*******`                              |

> 行政区识别排除「小区/园区/校区/社区」等非行政区「区」结尾复合词，避免误留门牌级信息。

### 3.4 姓名掩码 `mask_name`

| 场景      | 规则           | 示例              |
| --------- | -------------- | ----------------- |
| 空 / None | 返回空串       | `""`              |
| 单字      | 整体掩码       | `张` → `*`        |
| 多字      | 保留首字 + `*` | `张小明` → `张**` |

> **AI 出站**的学生姓名不走 `mask_name`，而走 `app/utils/anonymize.py::Anonymizer` 映射为「学生01」（请求级稳定、可还原）。

## 4. 加密方案（设计，代码待专项立项）

> **本批不做代码加密落库**（重工程：模型 + 读写 + 迁移 + 密钥管理），此处给出完整设计供立项。诚实标注：**代码落地待专项立项**。

### 4.1 算法与密钥

- **算法**：`AES-256-GCM`（认证加密，密文 + nonce + tag，防篡改）。参考 `docs/contracts/00-data-layer-baseline.md` §3.1.4 `agent_llm_configs.api_key_encrypted` 预留的 AES-256-GCM 思路。
- **密钥**：经环境变量 `DATA_ENCRYPTION_KEY`（32 字节 Base64）注入，生产建议走 **KMS / 云凭据**。**禁止硬编码**，禁止提交进代码/打包产物（本项目已有凭据泄露教训，见记忆）。
- **密钥轮换**：预留 `key_version` 字段，解密时按版本查主密钥；轮换即旧版本只解密不解密写入。

### 4.2 加密字段范围（写时加密，读时解密）

| 表              | 字段                                            | 说明                                                                       |
| --------------- | ----------------------------------------------- | -------------------------------------------------------------------------- |
| students        | student_number / phone / parent_phone / address | 核心 PII，写库前加密                                                       |
| users           | phone                                           | 账号联系方式                                                               |
| health_checks   | symptoms / handle_notes                         | 若按 L4 加密，需与「班主任查看」需求平衡——建议加密但班主任行权解密         |
| parent_students | parent_id / student_id                          | 关系链加密需评估外键/查询影响（JOIN 无法直接走密文），建议仅对敏感快照加密 |

### 4.3 解密授权

- **解密场景**：编辑学生信息、行权导出（`/admin/rights/data`）、班主任查看健康明细。
- **禁止解密场景**：AI 出站一律不解密（AI 拿到的始终是匿名化/掩码后的数据）。
- **审计**：解密动作写入 `access_logs`（E03+E14 已建表），记录 who/what/when。

### 4.4 回退策略

- 解密失败（密钥缺失 / 密文损坏）→ 返回 `None` 或 `field_masking` 掩码，**不阻断主流程**。
- 老数据未加密 → 读取时自动识别密文前缀（如 `aesgcm:`）与明文，渐进式加密。
- 迁移路径：新增列存密文 + 存量明文在行权/编辑时惰性加密，不一次性全量迁移。

### 4.5 与 AI 出站的关系

加密落库后，AI 出站仍保持「不发送 PII」：花名册工具不读 phone/parent_phone/address/birthday；MySQL 工具结果集剥离敏感列；姓名匿名化。**加密是纵深防御，AI 脱敏是出站闸门，二者不互相替代。**
