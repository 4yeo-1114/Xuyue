## 一、双库审计结论速览（2026-08-30 两个只读 agent 实测）

### MySQL 主库（67 表，127.0.0.1:3306/grade）—— 结构面高度就绪 B+

| 维度        | 结论                                                                                                                                                                                                                                                 |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 主键形态    | **67 表全为 varchar(36) UUID 单列主键**，无自增、无复合键、无无主键表 → 迁移友好度极高                                                                                                                                                               |
| FK          | 无 FK 环（3 处自引用可拆）、~120 条 FK 全部指向 varchar(36)；但 **40+ 个 `_id` 列无 FK 约束**（school_id 全系、response_logs、exam_scores.class_id、R4 教材级联）                                                                                    |
| 数据质量    | school_id R2 回填已闭环（无孤儿）；UUID 完整性 100%（唯一例外 `indicator_definitions` 31 条 `ind-*` slug）；**36 张空表**；`exam_scores.grade` 100% NULL（13,850/13,850）；`students`/`users` 多列全 NULL（新补列未回填）                            |
| 方言绑定    | 17 个 model 27 个 `mysql.JSON` 列 + **16 个 LONGTEXT 实为 JSON 文本**的列；`database.py` 的 `_ensure_*` MySQL DDL；`docs/migrations` 12 个 .sql + `portfolio_alter.sql` 全 MySQL 语法；`backfill_wrong_question_kp.py` 的 `NOW()`/`ON DUPLICATE KEY` |
| 利好        | `multi_project_settings.py` 已具备 **db profile 热切库能力**（天然回滚开关）；AI 助教 SQL 执行器已内置 MySQL→PG 翻译层（剥反引号/IFNULL→COALESCE/布尔字面量）；141 个 datetime 列均无服务端 `ON UPDATE`（updated_at 走应用层）                       |
| 模型-库偏差 | `student_memories` 表在库但**模型未注册**（create_all 不建）；死模型 `evaluation_archives`/`wrong_question_review`（模型在、库无表）；`exam_scores`/`student_analysis`/`student_score_history` 等 6 表有**库补列模型缺失**                           |

### PG 家长库（843 表，localhost:5432/grade）—— 融合数据层就绪、安全与规范债必须前置

| 维度          | 结论                                                                                                                                                                                                                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 表量          | 843 表但 **~700 张为备份/导入过程表**（`questions_bak_20260811` 1.3GB、`math_bulk_backup_bXXX` 500+）；真实业务 134 张，库体积 5.6GB 近半是垃圾                                                                                                                                 |
| 核心资产      | 题库 questions 1,219,999（2.8GB）/ question_kp 1,486,106 / knowledge_points 4,087 / difficulty_gold 7,483 —— **结构清晰、可直接以 PG 为权威**                                                                                                                                   |
| 家长端业务    | **体量极小**（用户 31 / 学生 12 / 练习 107 / 报告 245），demo 早期，融合成本低但非迁移主体                                                                                                                                                                                      |
| 类型方言      | 无原生 uuid 类型（全 varchar(36)）；**json(110 列) vs jsonb(3 列) 混用**；timestamptz(281) vs timestamp(22) 混用；8 种自定义 ENUM；bool 与 int4 0/1 混用                                                                                                                        |
| **P0 安全债** | PG `users.plain_password` **明文密码残留 9 行**（MySQL 已在 C4 修复删除）；**`grade_school_ro` 只读账号不存在**——主平台资产连接实际用 `postgres` 超级用户，权限过宽                                                                                                             |
| P1 冲突       | **18 张同名表**（users/students/exams/exam_scores/classes/knowledge_points 等，需合并矩阵）；`identity_link` 仅 1 行（家长端 12 学生 vs 主平台 1,222 学生无自动匹配）；**错题三轨制**（MySQL student_wrong_questions 17,549 / MySQL wrong_questions 0 / PG wrong_questions 24） |
| P2            | FK 环（circle_posts 自引用等）、json 数组伪 FK、PII 分散 5+ 表、`data_sharing_consents` **0 行**（未成年人合规缺同意链路）                                                                                                                                                      |

## 二、就绪度结论

**结构面高度就绪**（全 UUID 单列主键、无 FK 环、无自增 = 迁移友好），**数据面需少量前置清理，安全债必须先清，不建议直接开迁**。`app/assets/` 只读模型与 PG 实际列对齐度好（仅 knowledge_points 多 4 个 PG 实有列未映射）。

## 六、协作边界（对齐白板 8.6）

对齐另一 CC 白板 8.6 立场（P3 迁移前**不过度耦合**）：

- **记忆系统 + 合成学生仿真场先灵犀 PG 跑**，学校端数据走只读接口桥接入；P3 迁移清单**不碰灵犀 PG 侧新建的记忆相关表**（memory_events 等）。
- **只读接口桥预留**：学校端未来暴露给灵犀的只读数据（批改结果/掌握度/趋势/薄弱点）走轻量只读 API，本计划 F3 阶段一并回归，不做跨库强关联。
- `memory_events` 协议中立：schema 不变，学校端将来 0 改造接入；本计划不把 memory_events 挂 MySQL。
- 归另一 CC：`grading/` 置信度路由、记忆系统 M1-M3、合成学生仿真场（`difficulty_gold` 校准锚依赖 PG 资产链路，本计划不动）。
- 迁移涉及 `docs/migrations/` 重写时先与另一 CC 确认无依赖（记忆系统 M1 落点在 agent_conversations，迁移后归 PG 侧）。
