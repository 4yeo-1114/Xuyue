# 融合前端 · 数据接入后的前端变化设计（2026-08-30）

> 用户指令："把数据接入后，前端的变化，你要查看之前灵犀前端的展示方式，结合项目本身的前端，看看怎么设计，workflow 安排。"
> 输入：P3 业务库迁移完成（63 表并入 PG public，学校业务数据与家长端 PG 资产**同库**）+ 两份前端 explore 调研（主项目学校端 / 灵犀家长端）。
> 本文 = 设计方案 + workflow 编排。执行改动走 dispatch Agent + worktree 隔离。

## 一、两仓前端现状对比（调研结论）

| 维度   | 主项目学校端（grade-buddy-scan-main）                                              | 灵犀家长端（parent-h5）                                                                                                |
| ------ | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 角色   | **教师/学校管理员**（操作工具）                                                    | **家长/学生**（学情洞察+激励）                                                                                         |
| 技术栈 | React 18 + TS + Vite + **shadcn/ui** + Tailwind + TanStack Query v5 + **recharts** | React 18 + TS + Vite + **纯 Tailwind 自绘**（无组件库）+ Zustand + TanStack Query v5 + **ECharts(仅折线/柱)+手写 SVG** |
| 架构   | 单页 + 侧边栏 navId（30+ 功能页，TopHeader 全局筛选）                              | HashRouter ~100 路由 + 底部 5 Tab + **配置化首页分区**（SectionRenderer + 拖拽布局）                                   |
| 数据源 | MySQL 业务（现已迁 PG）+ PG 资产（school-assets）                                  | PG 家长业务 + PG 资产                                                                                                  |
| 强项   | 考试分析/班级对比/驾驶舱/组卷                                                      | **掌握度可视化体系 / 错题诊断卡 / 成长激励体系 / 班级周报**                                                            |

**关键事实**：两仓 UI 体系完全不同（shadcn vs 自绘、recharts vs ECharts/手写SVG），组件**不能跨仓直接 import**，只能"借鉴模式→各自重写"。

## 二、融合设计原则（3 条）

1. **端不合并、数据打通**：教师端与家长端服务不同角色，各自 UI 体系不动。P3 已统一数据层，两端展示同一套业务数据的不同视角。
2. **展示模式对齐**：灵犀成熟的掌握度/错题可视化 → 学校端**借鉴重写**；学校端考试分析 → 家长端可选接入。不引入跨仓组件依赖。
3. **数据接哪端算哪端**：学校端接「业务+资产」闭环；家长端通过只读接口桥接学校业务数据（对齐白板 8.6，不过度耦合）。

## 三、学校端前端变化（数据接入后 · 4 项按优先级）

P3 后 `knowledge_points`（PG 4087 资产）+ `wrong_question_kp_bridge`（17,052 行，命中 75.1%）+ `student_wrong_questions`（17,052 行，B3 已带 kp 字段）同库可用，学校端最大变化 = **把"掌握度/薄弱点/错题"从空态/反推值变真实数据闭环**。

### P1 掌握度真实化（最弱项 → 实数据）

- **现状**：驾驶舱"知识掌握度"恒空态（`mastery_available=false`）、知识图谱节点掌握度是 `100-risk` 反推、学生能力雷达无 AI 诊断时硬编码 0 分。
- **数据源**：PG `knowledge_points`（4087）+ `student_wrong_questions.knowledge_point_id` + `wrong_question_kp_bridge` → **班级/学生知识点掌握度 = 该知识点错题分布聚合**（可立即做的真实数据；非 AI 诊断，标注"由错题分布派生"）。
- **改动**：①驾驶舱 MasteryDistribution 接聚合 API ②知识图谱节点换真实掌握度 ③学生雷达接班级聚合（替代硬编码）。
- **借鉴**：灵犀 `AdaptiveProgressChart`（掌握度堆叠条+知识点明细）改 N 学生聚合；`KnowledgeGraphCanvas` 掌握度三色节点。

### P2 错题诊断闭环（bandit + kp 锚点）

- **现状**：前端错题卡只显示题目文本/`error_type` 粗分类，**无 kp 锚点展示**；bandit 后端（`GET /recommend/wrong-questions` + `POST /recommend/wrong-questions/click`）**前端未接**。
- **改动**：①错题卡加知识点 chip（kp 锚点）②加"变式推荐"卡（bandit 返回）③点击上报埋点（reward 闭环）。
- **借鉴**：灵犀 `WrongBookPage` 错题诊断卡（错因 taxonomy `概念不清/方法缺失/审题错误/计算失误 × 细分` + 三色复习态 + 变式核对流，`ERROR_TYPE_KEYS` 常量已与后端对齐）。

### P3 薄弱点统一数据源

- **现状**：年级/班级/知识图谱三处薄弱点来自 `class-analysis/report`（AI 快照），驾驶舱走 `knowledge_points`（空），**同一概念三套数据源口径不一致**。
- **改动**：统一为「错题→知识点实时聚合」口径（P1 派生数据复用），三处同源。

### P4 班级周报 + 班级知识点掌握分布（借鉴灵犀）

- **借鉴**：灵犀 `ReportPage` class tab 班级周报卡（班级均分/作业完成率/优秀数 3 格 + 班级共性薄弱点按错误率排序 + 下周预告），学校端"班级学情概览"几乎零改可用。
- **借鉴**：`RadarChart` 五维雷达 + **班级均分虚线叠加层**（"学生 vs 班级"对比是学校端刚需）。
- **借鉴**：`ScoreTrendChart` 成绩趋势折线 + 百分位排名 + 波动稳定度（学校端成绩分析增强）。

## 四、家长端前端变化（后续 · 需跨仓协调）

## 七、Workflow 编排（定稿 · 2026-08-30 用户拍板）

- **阶段 1 · 后端接口（back_end 仓，并行 3 agent）**：

- **阶段 2 · 学校端前端（grade-buddy-scan-main，并行 3 agent，worktree 隔离）**：
