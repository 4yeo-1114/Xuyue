## 二、问题根因清单

### 根因 1（决定性）：百度 VLM 作答框字段读错，全卷 0 个作答槽

| 项 | 内容 |
|---|---|
| **现象** | 选择题 ✓/× 落在题干行尾；填空题完全没有批改痕迹；一批卷「看起来没批改」 |
| **根因** | 官方文档定义作答框在 `result.qus_result[].location.ans[].ans_location`；代码读的是 `location.ans_location`（该键不存在）→ `answer_bboxes` 恒为空 |
| **证据** | 实测 4 份真卷：题干框正常返回，作答框 **0/26、0/3、0/2、0/8**；同一份原始 JSON 里第 1 题躺着 15 个真实作答框（裁图确认是学生手写字母） |
| **修复点** | `reference_vlm_grading.py` 新增 `_answer_locations_from_raw()`，同时兼容 `location.ans[].ans_location`（切题模式）、`location.ans_location`（切题审查回写）、`item.ans_location`（合成题）；去重并按阅读序排序 |
| **效果** | 全卷作答槽从 0 → 40（2105 科学卷） |

### 根因 2：题号口径错位，「1–15 答题表格」被当成第 1 题

| 项 | 内容 |
|---|---|
| **现象** | 修好根因 1 后准确率反而降到 37.9%（学生答案对到了别的题的答案上） |
| **根因** | `only_split=true` 不返回题干文字，`display_index` 只是返回顺序；卷首的答题表格被算作第 1 题，其后的第 1 题变成第 2 题……整体错位一格 |
| **修复点** | 新增 `_printed_number_candidates()`（识别「13.小苏打…」粘连题号 + 表格裸数字，**不用任何固定题号区间**）与 `_anchor_printed_numbers()`（题号落在框内/框上沿 60px、同一题号只认领一次）；撞号顺延到空号 |
| **效果** | 题号恢复为卷面真实题号 |

### 根因 3：一块多框的答题表格共用同一份标准答案

| 项 | 内容 |
|---|---|
| **现象** | 同一份标准答案被 15 个格子同时消费，9 错 1 未判 |
| **根因** | 百度把「1–15 答题表格」整块返回（含 15 个作答框），系统当成一道题 |
| **修复点** | 新增 `_split_answer_grids()`：一框一题号（按 x 中心配对、题号互不重复）才拆分，拆成 N 道单框题；拆不了就记录原因 |
| **效果** | 15 个格子各自按题号判分 |

### 根因 4：选择题硬编码题号区间 9–14

| 项 | 内容 |
|---|---|
| **现象** | 题号不在 9–14 的卷子，全页 OCR 涂卡词典恒为空 |
| **修复点** | 删除 `if not (9 <= num <= 14): continue`，改为不设白名单（多余题号无块消费也无害） |
| **效果** | 不再有纸面相关硬编码 |

### 根因 5：选择题提示词只认「涂黑的方框」，不认手写字母

| 项 | 内容 |
|---|---|
| **现象** | 学生手写连笔 `B` 被读成 `13`，随后被硬判为错 |
| **修复点** | `_CHOICE_READ_PROMPT` 改为「涂卡或手写字母都要认，答案一定是 A-D、绝不会是阿拉伯数字」；另加保护：标准答案是单个字母而读出的内容不含任何 A–D 字母 → **显式「待人工确认」**，不硬判 |
| **效果** | 第 6 题从「13/错」变为「B/对」 |

### 根因 6：填空题多空题只消费第一空

| 项 | 内容 |
|---|---|
| **现象** | `5.1 B 5.2 D` 这样的多空答案，第二空永远没人判 |
| **根因** | 每道填空题只切出 1 个 slot，判分只查 `N_1` |
| **修复点** | 新增 `_expected_blanks_for_block()`：同题 `N_1..N_k` 全部收集，多空时以「第1空：…；第2空：…」交给逐空判分；**块自带独立空号时不合并**（保护原有的逐块判分语义） |

### 根因 7：答案解析正则截断小数 / 负号 / 范围

| 项 | 内容 |
|---|---|
| **现象** | `1. 0.5` 解析成 `0`，`1.08×10⁵` 变 `08`，还造出幽灵题号 |
| **证据** | 实测 `'1. 0.5 2. 1.08 3. 2'` → `{'1_1':'0','5_1':'2','1_1':'08','3_1':'2'}` |
| **修复点** | 重写为「按题号起点切段 + 题号必须递增」：答案体不按字符集截断，`0.5`、`1.08×10⁵`、`-3`、`2-3 m` 完整保留；`_RANGE_RE` 只认纯选项字母，避免把数值范围当题号范围 |

### 根因 8：所有失败路径静默 `continue`，老师端完全看不见

| 项 | 内容 |
|---|---|
| **现象** | 填空题「像被漏掉」——不是没批，是没痕迹 |
| **修复点** | 无标准答案 / VL 读不准 / 抽取失败 / 转写含 `[?]` / 选择题识别失败，全部改为：`read_uncertain=True` + `needs_review=True` + `block["reason"]` 写明原因 + `block["result"]="待确认"` + 打印含 slot_id 的日志；收尾再兜底扫一遍，任何「有标准答案却无判定」的块一律标「待确认」 |

### 附带修复：带圈数字导致整卷崩溃

| 项 | 内容 |
|---|---|
| **现象** | 25英语卷切题直接抛 `ValueError: invalid literal for int(): '④'` |
| **根因** | Python `str.isdigit()` 对 `④`、`²` 返回 True，但 `int()` 失败 |
| **修复点** | 4 处 `isdigit()` 转 int 的地方全部加 `isascii()` 校验 |

## 六、仍存在的风险与建议

### 必须关注
1. **QPS 配置偏离官方限制**：文档 create_task QPS=2、get_result QPS=10，代码默认 30。
   生产环境若并发批改，会频繁撞 `error_code=18`（限流），表现为「批改变慢/失败重试」。
   **建议**：`.env` 显式设置 `BAIDU_CREATE_QPS=2`、`BAIDU_GET_RESULT_QPS=10`，
   或升级百度侧配额后再调高。
2. **图片未按文档 urlencode**：目前靠 JSON body + JPEG 压缩能用，但属于偏离文档。
   大尺寸原图（>10M）或特殊场景可能被拒。**建议**：按文档改为 form-urlencoded 提交。
3. **错误码覆盖不全**：216201（图片格式错误）、216630（识别失败）目前统一抛 RuntimeError，
   用户看到的是原始错误串。**建议**：映射为中文可读提示。

### 需要更多样本
4. **只有 2105 科学卷有人工核对的真值**（15 题 100%）。其余 6 卷只验证了「不漏批」，
   **准确率尚未用人工标答验证**。建议每科各抽 2–3 份、由任课老师标注正确答案后复测。
5. **英语卷题号锚定**：初一26 英语卷锚定结果曾出现 `[6, 2]`（应为 `[1,2]`），
   已定位为「题框与题号相对位置不满足框内/框上沿 60px」。当前不影响该卷判分（全部待确认），
   但需要放宽匹配条件或用 x 范围约束二次校准。
6. **连笔字母识别**：第 6 题靠提示词修复解决，但属于概率性改善。建议长期采集
   「被读成数字/乱码」的样本，评估是否需要引入「字母候选集约束」的二次校验。

### 仍需人工复核的场景（设计如此）
- 手写潦草到 VL 自报「待确认」→ 保持待确认，不画符号，老师端显示原因。
- 标准答案缺失 → 待确认并写明缺失键名。
- 多空题标准答案空数多于作答区切出的框数 → 逐空判，缺的空的按未命中处理。
