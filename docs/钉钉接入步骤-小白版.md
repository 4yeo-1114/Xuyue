# 叙阅接入钉钉 · 小白版操作手册

> 参考：钉钉开放平台 SSO 文档 + 《钉钉家校作业系统-三项能力开工实施方案》
> 适用：把「叙阅」挂到学校钉钉的工作台上，老师点图标直接进，不用再输账号密码

---

## 零、先用大白话说清楚在干什么

打个比方：

| 现实 | 对应 |
|---|---|
| 学校 = 一栋大楼 | 学校的钉钉组织 |
| 钉钉 = 大楼的门禁 | 钉钉账号体系 |
| 叙阅 = 楼里的一间办公室 | 你做的这个系统 |
| **接入钉钉** | 让老师**刷工牌**就能进这间办公室 |

**老师看到的效果**：

```
打开钉钉 → 点底部「工作台」 → 看到「叙阅」图标 → 点一下 → 直接就进去了
```

**没有登录页、不用输密码**。

这背后发生的事（一句话）：
> 钉钉告诉叙阅「来的人是谁」，叙阅查一下自己数据库里有没有这个人，有就放行。

---

## 零之二、⚠️ 先别找学校！用你自己的钉钉先跑通

**结论：完全可以，而且强烈建议这么做。**

手册下面写「找学校要 6 样东西」，那是**最后上线**时的要求。
**开发和联调阶段，你用自己的钉钉就行**，代码一模一样，只是换套参数。

### 为什么建议先自己来

| | 自己建组织 | 学校 |
|---|---|---|
| 审批权限 | **自己是管理员，自己点同意，秒批** | 要等管理员，可能走流程 |
| 建应用 | 随便建，出错了删掉重来 | 要跟学校打招呼 |
| 测试数据 | 自己拉几个同事进来随便试 | 得等学校录名单 |
| 搞坏了 | 无所谓 | 影响生产，压力大 |
| 成本 | **免费** | — |

### 自己怎么搭（约 20 分钟）

```
1. 手机下载钉钉，用自己手机号注册
   ↓
2. 注册时选「创建企业/团队」，随便起个名（如「叙阅测试」）
   ↓ 现在你就是这个组织的主管理员
3. 浏览器打开 open-dev.dingtalk.com，用同一个账号登录
   ↓
4. 应用开发 → 创建应用 → 网页应用（H5微应用）
   ↓
5. 到手的 corpId / AppKey / AppSecret / AgentId  → 直接填进代码
   ↓
6. 权限管理 → 要什么点什么 → 申请 → 你自己批 → 秒过
   ↓
7. 发布版本 → 工作台可见范围选「全部员工」
   ↓
8. 手机钉钉 → 工作台 → 点自己那个图标 → 测免登
```

### 自己测能测到什么程度

| 能力 | 自己能否测 | 说明 |
|---|---|---|
| **免登（SSO）** | ✅ **完全能** | 这才是你现在最想验证的，自己测完全够 |
| 应用创建 / 权限 / 发版流程 | ✅ 完全能 | 跟真实环境一模一样 |
| 工作台图标、手机+PC 双端 | ✅ 完全能 | |
| 消息推送（工作通知） | ✅ 能 | 发给自己或拉的同事 |
| 群机器人发消息 | ✅ 能 | 自己建个群把机器人拉进去 |
| **家校通讯录（学生/家长）** | ⚠️ **可能不行** | 需要「新教育」权限，**个人组织申请可能被拒**，这块得等学校 |

> **换句话说**：
> - **免登** → 自己就能测通，**不用等学校一天**
> - **家校通讯录** → 这块是教育行业专属权限，个人组织大概率拿不到，必须学校给

### 往后怎么切到学校

代码里凡是 `corpId`、`AppKey`、`AppSecret`、`AgentId` 都**不要写死**，放进配置文件/环境变量。

到时候只要：

```
1. 学校给一套新参数
2. 换掉配置里的 4 个值
3. 重新发布一版
```

**代码一行都不用改。**

## 一、上线前，找学校要这 6 样东西

> ⚠️ 这一节是**最后上线**才需要的。开发和联调阶段看上面「零之二」就行。



这 6 样**缺一样都干不了**，而且大部分只能学校给：

| # | 要什么 | 长什么样 | 找谁要 | 干嘛用 |
|---|---|---|---|---|
| 1 | **corpId** | `dingc1640dc01528...` 一串字符 | 学校钉钉管理员 | 告诉钉钉「是哪个学校」 |
| 2 | **AppKey / AppSecret** | 两个字符串 | 建完应用后自动生成 | 叙阅跟钉钉说话的「账号密码」 |
| 3 | **AgentId** | 一串数字 | 建完应用后自动生成 | 标记「用哪个应用发消息」 |
| 4 | **家校通讯录读取权限** | 后台一个开关 | 学校主管理员点「同意」 | 读全校班级、学生、家长名单 |
| 5 | **家校通讯录已经录好了** | — | 学校管理员 | ⚠️ 最常见的坑：**没录数据，接口通了也是空的** |
| 6 | **服务器公网 IP** | 如 `120.26.101.0` | 你自己的服务器 | 有些接口会检查「谁在调用」 |

> ⚠️ **第 5 条特别提醒**：很多学校钉钉里只有老师的通讯录，**没有家校通讯录**（学生、家长）。
> 如果学校没录，学生和家长的功能全废。**开工前一定要抽查 3 个班**，核对人数和线下名册对不对得上。

## 二、第一步：在钉钉后台建应用（约 30 分钟）

### 2.1 登录

浏览器打开 **https://open-dev.dingtalk.com/**，用**学校管理员**账号登录（右上角记得切到学校那个组织）。

### 2.2 创建应用

```
应用开发 → 创建应用 → 选「网页应用（H5 微应用）」
```

- **名称**：`叙阅` 或 `XX学校作业批改`
- **图标**：256×256 的 PNG（就是工作台上那个方块图标）

### 2.3 填地址（⚠️ 最容易出错的地方）

在「开发管理」里填：

| 填什么 | 填什么值 | 注意 |
|---|---|---|
| **应用首页地址** | `https://xuyue.6108.net/dingtalk/entry` | **必须 HTTPS**，且是你服务器能打开的域名 |
| **PC 端首页地址** | 跟上面填一样 | 两端都要填，否则一边能进一边白屏 |
| 服务器出口 IP | 你服务器的公网 IP | |
| 可信域名 | 跟首页地址同域 | |

> 💡 你现在已经有 `xuyue.6108.net` 和 HTTPS，这步直接能用。

### 2.4 申请权限

进「权限管理」，搜「新教育」，勾选：

- ✅ 家校通讯录读取（部门 / 人员 / 人员关系）
- ✅ 消息通知（发工作通知）
- ✅ 企业内机器人发送消息
- ✅ 群会话读取

勾完点「**申请权限**」→ 学校管理员审批。

### 2.5 发布版本（⚠️ 改了必须重新发）

```
版本管理与发布 → 填版本号 → 发布
```

> ⚠️ **权限变了、地址变了，都必须重新发一个版本才生效**。
> 「接口报 404」「免登白屏」十次有八次是——**改完忘了发布**。

### 2.6 设置谁能看见图标

```
应用能力 → 工作台 → 设置可见范围
```

**先只给一个试点班的老师**，验收没问题了再放开全校。

## 三、第二步：叙阅后端加两个接口

### 3.1 先搞个「跟钉钉对话」的小工具

跟钉钉说话需要一个**通行证**（access_token），它 2 小时过期。

所以写个小工具：**自动拿、自动续、自动缓存**。

关键点：
- 钉钉有**新旧两套**地址，别搞混：
  - `oapi.dingtalk.com` / `api.dingtalk.com/topapi/*` → **旧的**（家校通讯录、免登用它）
  - `api.dingtalk.com/v1.0/*` → **新的**（发群消息用它）
- 通行证提前 5 分钟刷新，避免刚好卡在过期那一秒

### 3.2 接口 A：读学校的班级和学生

这一步是**把学校钉钉里的名单搬到叙阅**。

要读的东西像一棵树：

```
学校
 └─ 年级（一年级、二年级…）
     └─ 班级（一年级3班）
         ├─ 老师（谁是班主任）
         ├─ 学生
         └─ 家长  ← 还要知道「谁是哪个孩子的家长」
```

**要循环调用 3 个钉钉接口**：

| 步骤 | 调什么 | 拿到什么 |
|---|---|---|
| 1 | 获取部门列表 | 所有年级和班级 |
| 2 | 获取人员列表 | 每个班里的人（老师/学生/家长） |
| 3 | 获取关系列表 | 家长 ↔ 学生 的对应关系 |

> ⚠️ **钉钉有个奇怪的限制**：每页最多 30 条，而且只能一页页翻。
> 一个 1000 人的学校要调**几十次**。所以这不是实时接口，得**同步一次、存到自己数据库**。

**建议建 4 张表**（跟叙阅现有的表放一起）：

```
edu_dept        班级/年级的树
edu_user        这个人是谁、在哪个班、什么角色
edu_relation    谁是哪个孩子的家长
edu_class_group 班级 ↔ 钉钉群的对应（后面发消息要用）
```

然后**每天同步一次**（或者用钉钉的「事件订阅」做实时同步）。

### 3.3 接口 B：免登（核心！）

这是**老师点图标之后发生的事**：

```
① 老师点图标
    ↓
② 前端跟钉钉要一个「临时进门条」（authCode）
    ↓
③ 后端拿「进门条」跟钉钉换「这个人是谁」（userid）
    ↓
④ 叙阅查数据库：这个 userid 对应哪个账号？什么角色？
    ↓
⑤ 给这个人发一张叙阅自己的「门卡」（就是你现在的 JWT）
    ↓
⑥ 前端存下门卡，进主页
```

**⚠️ 三个必须知道的规矩**：

| 规矩 | 说明 |
|---|---|
| **进门条只能用一次** | 用过了就作废，不能重试 |
| **5 分钟就过期** | 超时得重新要 |
| **绝对不能缓存** | 缓存了别人就能拿你的条进门 |

**接口大概长这样**：

```
POST /api/v1/auth/dingtalk-login
请求：{ "code": "前端拿到的进门条" }
返回：{ "ok": true, "access_token": "叙阅自己的JWT", "role": "teacher" }
```

## 四、第三步：身份对接（⚠️ 最关键、最容易翻车）

### 4.1 问题在哪

钉钉说「来的人是 `manager7975`」，但叙阅数据库里没有这个 ID。
**必须有一张对照表**，把「钉钉的人」翻译成「叙阅的人」。

叙阅现在的用户表有这些可用字段：

```
id              内部ID
email           邮箱（唯一）
phone           手机号   ← 最好用它来对
display_name    姓名     ← 重名风险大，只能兜底
roles           角色
```

### 4.2 三种对接方式，按可靠度排

| 方式 | 怎么做 | 可靠度 | 工作量 |
|---|---|---|---|
| **① 手机号匹配**（推荐） | 钉钉拿手机号 → 查叙阅 users.phone | ⭐⭐⭐⭐ | 小 |
| **② 管理员手动绑定** | 后台加一列 `dingtalk_userid`，管理员一个个绑 | ⭐⭐⭐⭐⭐ | 中（要人操作） |
| **③ 姓名匹配** | 姓名对上就算 | ⭐⭐ | 最小 |

**建议**：**① 为主 + ② 兜底**。

即：先按手机号自动匹配；匹配不上的，提示「请联系管理员绑定」，管理员在后台手动绑。

### 4.3 匹配不上怎么办（一定会遇到）

几种典型情况：

- **老师不在家校通讯录里**（家校通讯录只管学生和家长，老师可能在员工通讯录）
- **一个家长有两个孩子**，钉钉会给两条记录
- **手机号换过**

**兜底方案**：做个「绑定申请」页面——老师填手机号，管理员审核通过后绑定。

### 4.4 安全红线（涉及学生成绩，必须守住）

```
❌ 前端传过来的 userid / 角色，一律不信
   → 身份只能由「后端拿 code 换来的结果」推导

❌ 不能拿钉钉的「管理员」标记当叙阅的超管
   → 免登只解决「你是谁」，「你能看什么」得由叙阅自己的权限判定

✅ 查数据必须带上班级过滤
   → 班主任只能看本班，家长只能看自己孩子
```

## 五、第四步：前端做个「钉钉入口页」

做一个单独的页面（比如 `/dingtalk/entry`），逻辑很简单：

```
1. 页面加载
2. 问钉钉：给我一张进门条
3. 把进门条发给叙阅后端
4. 后端说「进来吧」，就跳到主页
```

**⚠️ 一个救命的小细节**：这个页面**必须显示错误提示**。

因为钉钉里如果出错，默认是**一片白屏**——什么提示都没有，你会完全不知道哪出问题了。

所以：失败时一定要在页面上写清楚「免登失败：xxx」。

另外，**用普通浏览器打开这个页面时**，要提示「请在钉钉工作台中打开」。

## 六、第五步：怎么测

### 6.1 测试顺序（从易到难）

```
1. 先用 Postman 测「拿通行证」通不通
   ↓
2. 测「读班级列表」，看能不能拿到数据条数
     拿不到 → 学校没录家校通讯录（回去找第 5 样东西）
   ↓
3. 手机钉钉点图标，测免登
   ↓
4. PC 钉钉点图标，再测一遍（PC 端行为偶尔不一样）
```

### 6.2 常见错误对照表

| 现象 | 大概率原因 | 怎么办 |
|---|---|---|
| 页面白屏 | 没在钉钉里打开 / SDK 没加载 | 检查是不是在钉钉容器里 |
| `不存在的临时授权码` | 进门条用过了或超 5 分钟 | 每次进页面重新要一个 |
| `不合法的 access_token` | 用错 AppKey 的通行证 / 过期没刷新 | 检查通行证缓存逻辑 |
| 换到的人查不到 | 不在家校通讯录里 | 用手机号兜底 + 绑定页 |
| **PC 能进、手机白屏**（或反过来） | 两端首页地址不一致 / 没重新发版 | 两头都填 + **重新发布** |
| 工作台找不到图标 | 可见范围没包含这个人 | 加试点班 + 发版 |

## 七、另外两块能力（可以后做）

你给的方案里还有两块，SSO 通了之后可以接着做：

### 7.1 消息推送（老师家长收到通知）

| 要推什么 | 走哪条路 |
|---|---|
| 全班可见的播报（"今日作业已批改完"） | **群机器人**发到班级群 |
| 点对点催（"你家孩子还没交"） | **工作通知**发给家长 |

⚠️ **注意**：群里**不要出现分数和排名**，个体成绩走私聊或免登页。

### 7.2 家长在钉钉里看孩子作业

需要上面两块都通了，再做家长的页面。

## 八、工期估算

| 阶段 | 内容 | 谁做 | 时间 |
|---|---|---|---|
| Day 0 | 找学校要齐 6 样东西 | 学校 + 你 | 1 天 |
| Day 1 | 建应用、配权限、发版 | 学校管理员 | 半天 |
| Day 2–4 | 后端：通行证工具 + 通讯录同步 | 后端 | 3 天 |
| Day 3–5 | 后端：免登接口 + 身份映射 | 后端 | 2 天 |
| Day 4–6 | 前端：入口页 + 错误提示 | 前端 | 2 天 |
| Day 7 | 联调 + 试点班验收 | 一起 | 1 天 |

**合计约 7–10 个工作日**（1 后端 + 1 前端）。

**其中最耽误时间的不是写代码，是等学校**：
- 等管理员审批权限
- 等学校把家校通讯录录好

**建议**：谈的时候就先把这 6 样要过来，别等开发完了才要。

## 九、最容易翻车的 3 个点（再强调一遍）

```
① 家校通讯录没数据
   接口全通，就是返回空。→ 开工前抽查 3 个班

② 改完配置没重新发布版本
   改地址、改权限 → 必须「发布」→ 否则死活不生效

③ 班级群的 ID 拿不到
   钉钉客户端界面上看不到「群的ID」，
   只能靠：建群时保存 / JSAPI 转换 / 机器人入群回调 三条路之一拿到
```
